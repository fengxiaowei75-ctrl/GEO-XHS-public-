数据生产链路

从 note_id 或 Excel 开始，逐步变成可检索、可分析、可复用的内容资产。

1

录入笔记

手工 note_id、笔记链接或 Excel 导入进入队列。

2

抓取详情

调用 Endata，写入标题、正文、发布时间、互动量、图片 URL 等原始数据。

3

图片解析

豆包/Ark Vision 逐图分析 OCR、画面结构、风格、内容逻辑和 image2 提示词。

4

资产聚合

豆包/Ark Chat 聚合笔记与图片信息，生成用户画像、痛点、需求、业务知识点。

5

向量化

豆包/Ark Embedding 把内容资产写入 pgvector，支持相似召回和洞察分析。

6

Web 使用

Vercel UI 读取资产、筛选笔记、调用生图和文案模型，并把调用写入监控。

业务功能区

当前 Web 侧主要是三个并列入口：市场需求洞察、爆文洗稿流、固定内容流。

市场需求洞察

输入 数据库内容资产、互动权重、时效权重、向量召回结果。
处理 筛选行业、痛点、人群、漏斗阶段、爆文结构和视觉资产。
输出 市场需求、热门内容方向、关键词、内容机会和模型调用监控。

爆文洗稿流

读取资产 输入 note_id 后自动回填标题、文案、人群画像、用户痛点、业务逻辑、知识点和多张图的原始提示词。
人工补充 可编辑全局风格、单图提示词、垫图、图片数量、是否统一配色与风格。
图像生成 每张图用自己的提示词作为主指令，整组上下文只作为理解参考，调用 Duomi gpt-image-2 创建任务并轮询查询。
改图与历史产出 单图可基于当前图和原提示词输入修改点；新旧版本都保留在同一组历史产出里。
社媒草稿 小红书、抖音、公众号、知乎四种类型使用豆包内容模型重写标题和正文，并生成 Markdown 文档。

固定内容流

定位 与市场需求洞察、爆文洗稿流并列的独立入口。
当前状态 已预留功能区，可后续接固定主题、固定栏目或标准化内容生产 SOP。
建议边界 复用同一内容资产、模型调用日志和草稿保存结构，避免新增孤立链路。

监控与治理逻辑

所有外部 API 调用都应进入同一套 provider/model/credential/call log 体系，便于看调用量、失败率和成本单位。

调用监控

Endata、豆包 Vision、豆包 Chat、豆包 Embedding、Ark 图生图、Duomi 图生图统一写入 geo_ops_api_call_logs。

创建与查询分离

Duomi 生图创建任务和任务查询分别记录，查询次数高通常来自轮询，不等于重复创建图片。

密钥边界

代码只保存环境变量名；真实 key 放在 Vercel Env 或云服务器 sync.env，加密备份走 sops/age。

数据库变更

表结构、字段、索引、触发器、函数、视图和 pgvector 变化必须先写 migration，执行前需要明确确认。

内容生产约束

这些规则直接影响爆文洗稿流的图像提示词和社媒草稿生成质量。

不能照搬

原笔记只能作为素材，不复刻标题、正文、账号、博主名、品牌露出或视觉水印。

日期必须谨慎

非实时新闻或明确历史案例不写具体日期，避免把旧截图日期误当成当前时间。

单图主指令

每张图优先遵循自己的数据库提示词；全局变量只帮助模型理解整组背景和风格，不替代单图目标。

整组一致性

需要统一风格与配色时，该规则优先于单图差异；不需要时保留每张图自己的结构和表达。
